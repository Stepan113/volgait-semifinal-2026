# Лабораторная работа 1 — автоматизация тестирования

Учебный проект для проверки сайта https://practice-automation.com/ с помощью PyTest и Selenium.

## Структура проекта

- `tests/test_home_page.py` — базовая проверка главной страницы.
- `tests/test_calendar.py` — позитивные и негативные проверки календаря.
- `pages/calendar_page.py` — действия и элементы страницы Calendars (Page Object).
- `tests/test_modals.py` — позитивные и негативные проверки модальных окон.
- `pages/modals_page.py` — действия с окнами страницы Modals (Page Object).
- `pages/form_fields_page.py` — чтение списка Automation tools через Selenium.
- `tests/conftest.py` — запуск и закрытие Chrome, скриншот при падении теста.
- `pytest.ini` — поиск тестов и сохранение результатов Allure.

## Главная страница

**Сценарий H01. Страница открывается.** Открыть главную страницу и проверить заголовок «Welcome to your software automation practice website!».

## Страница Calendars

Адрес: https://practice-automation.com/calendars/

На странице есть текстовое поле для даты в формате `YYYY-MM-DD`, всплывающий календарь с выбором месяца и года и кнопка Submit. Поле не помечено обязательным, поэтому пустое значение не включено в негативные проверки. Каждый автоматизированный тест начинает работу с новой страницы.

### Позитивные сценарии

| № | Действие | Ожидаемый результат |
| --- | --- | --- |
| P01 | Открыть страницу Calendars. | Видны поле даты и подсказка `YYYY-MM-DD`. |
| P02 | Ввести `2026-10-15` вручную и убрать фокус с поля. | Дата осталась в поле, ошибка не появилась. |
| P03 | Открыть май 2024 года и выбрать 15 число. | В поле записано `2024-05-15`. |
| P04 | Открыть март 2024 года, перейти к предыдущему месяцу и выбрать 29 число. | Открылся февраль 2024 года; в поле записано `2024-02-29`. |
| P05 | Открыть декабрь 2024 года, перейти к следующему месяцу и выбрать 1 число. | Открылся январь 2025 года; в поле записано `2025-01-01`. |
| P06 | Открыть январь 2024 года, выбрать июль в списке месяцев и нажать 4 число. | В поле записано `2024-07-04`. |
| P07 | Открыть февраль 2026 года, выбрать 2024 год в списке лет и нажать 29 число. | В поле записано `2024-02-29`. |
| P08 | Открыть февраль 2024 года и нажать 1 марта, видимое в сетке соседнего месяца. | В поле записано `2024-03-01`. |
| P09 | Ввести `2024-02-29` и отправить форму. | Показано подтверждение с этой датой. |

### Негативные сценарии

Для каждого случая ввести значение, убрать фокус с поля и нажать Submit. Ожидается сообщение `Please enter a valid date.`, поле отмечено ошибкой, подтверждение отправки не появляется.

| № | Значение | Что проверяется |
| --- | --- | --- |
| N01 | `2026/10/15` | Неверные разделители и формат. |
| N02 | `2026-13-01` | Месяца с номером 13 нет. |
| N03 | `2026-02-30` | В феврале нет 30 числа. |
| N04 | `2025-02-29` | В невисокосном году нет 29 февраля. |

## Страница Modals

Адрес: https://practice-automation.com/modals/

На странице есть простое окно (Simple Modal) и окно с формой (Form Modal). У формы обязательное поле Name; Email и Message можно оставить пустыми. Для дополнительного условия список Automation tools читается средствами Selenium со страницы https://practice-automation.com/form-fields/, объединяется через запятую и вводится в Message. Тесты используют этот список без жёстко записанных названий инструментов.

### Позитивные сценарии

| № | Действие | Ожидаемый результат |
| --- | --- | --- |
| P01 | Открыть Simple Modal. | Показаны заголовок `Simple Modal` и текст `Hi, I’m a simple modal.` |
| P02 | Открыть Simple Modal и нажать ×. | Окно скрыто. |
| P03 | Закрыть Simple Modal и открыть снова. | Окно повторно показано. |
| P04 | Открыть Form Modal. | Показаны заголовок и поля Name, Email, Message; Name обязательное. |
| P05 | Открыть Form Modal и нажать ×. | Окно скрыто. |
| P06 | Открыть Form Modal и нажать Escape. | Окно скрыто. |
| P07 | Получить список Automation tools через Selenium, заполнить форму, вставив список через запятую в Message. | В полях сохранён введённый текст. |
| P08 | Заполнить форму корректными данными, включая список Automation tools в Message, и нажать Submit. | Показано подтверждение отправки. |

### Негативные сценарии

| № | Действие | Ожидаемый результат |
| --- | --- | --- |
| N01 | Открыть Simple Modal и нажать Escape. | Окно остаётся открытым. |
| N02 | Открыть Form Modal и отправить форму с пустым Name. | Ошибка `This field is required.`, подтверждения нет. |
| N03 | Ввести имя и неверный email, затем отправить форму. | Ошибка `Please enter a valid email address`, подтверждения нет. |

## Запуск в PyCharm

1. Открыть проект и проверить интерпретатор: `.venv/bin/python` этого проекта.
2. Убедиться, что зависимости из `requirements.txt` установлены.
3. Нажать правой кнопкой на `tests/test_modals.py` и выбрать **Run pytest**. Можно запустить всю папку `tests`.

Каждый тест запускает отдельный Chrome/Chromium в фоновом режиме. На Ubuntu с Chromium из Snap используется установленный ChromeDriver, без поиска и загрузки другого браузера. Чтобы видеть браузер, временно закомментируйте строку `options.add_argument("--headless=new")` в `tests/conftest.py`.

## Запуск в терминале

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -v
```

Только календарь:

```bash
.venv/bin/python -m pytest tests/test_calendar.py -v
```

Только модальные окна:

```bash
.venv/bin/python -m pytest tests/test_modals.py -v
```

## Отчёт Allure

PyTest автоматически сохраняет результаты в `allure-results/` в корне проекта, независимо от рабочего каталога PyCharm. При падении теста с работающим браузером к результату прикладывается скриншот. Папка очищается перед каждым запуском тестов.

Для просмотра нужен отдельный Allure CLI. С Allure 2:

```bash
allure serve allure-results
```

С Allure 3:

```bash
allure generate allure-results
allure open allure-report
```
